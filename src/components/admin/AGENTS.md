# Admin components

- Private admin, representative and store-terminal shells use OperationalGlass with an explicit path allowlist and temporary body tokens for portals; never theme public pages or change queries, permissions or print engines. Why: unified isolated appearance with operational safety.

- Display fiscal readiness via the authenticated fiscal_prontidao RPC, gated by finance.view, with no mutation controls. Why: one protected read-only report.
- Piece and maleta labels use enviarParaImpressora (hidden iframe) with explicit destination confirmation before browser print; station names live in Remessas and calibration remains in label search settings; never writes codes or stock, nor confirms physical success. Why: browsers cannot select a physical device and A4/Argox destinations must not be confused.
- Collaborator overview uses only actor-authenticated montagem_operacoes; scanner increments use montagem_item_operar and never infer authorship from existing composition. Why: atomic quantities and provable personal productivity.
- Maleta labels encode the existing kits.code and resolve through kit_identificacao_buscar; legacy QR tokens remain readable. Why: no parallel numbering and scoped identification.- Product registration (0210): order is category → banho → name; reference comes from produto_referencia_sugerir (prefix by produto_ref_prefixo, number continues the last created product of that prefix, never reuses), variants get product reference + next letter via variante_referencia_sugerir and inherit price/NCM/cost; SKU and internal code stay hidden but are still sent unchanged; NCM defaults to 71171900 by trigger; variant photo = product_media.variant_id. Cost fields are sent only after product_costs_read answered. Why: no retyping and no wiped costs.
- Product list renders one row per active variant (expandirPorVariante, paging stays per product); Quantidade = non-maleta stock_balances quantity minus reserved, shown only with stock.view. Consultant pickers search via consultora_termo_casa (name parts, current/old/legacy code, CPF) and label "[Cód. X] Nome" with masked CPF. Why: variants are distinct sellable pieces; staff identify consultants by code.
- Every product variant is born with a 5-digit barcode (variant_barcode_autofill, 0225), including the default 'Padrão' one; filled codes are never replaced and skipped sequence numbers are never reused. Why: new products must always be printable/scannable.
- CRM "Concluídos" (0301): a lead whose linked party (or CPF match when unlinked) has any non-cancelled kit cycle is concluded — `crm_lead_maleta`; `crm_filtrar` shows concluded leads only with `concluidas=true`, so Kanban/Lista/radar never show them. Test leads are archived via `crm_archive`, never deleted. Why: the funnel shows only people still to be converted, history preserved.
- Piece labels (0340): ring aro (number only, from variant size or 'Aro NN' label) prints right-aligned on the name line with reserved space, and the 'Aro NN' label is not repeated in the name; '2 lados' repeats the same block at segundoLado mm in one physical label (copies unchanged), chosen in a LadosEtiqueta placed right next to every printer button (lists included; local state per button, default 1 lado, never persisted, resets to 1 lado after that button sends); maleta labels never duplicate. Why: matches the folded ring tag without changing codes or calibration.
- Piece/consultant identification (0340–0342): piece searches go through pecas_buscar (reference first, then name parts/barcode/SKU) and stock lists also match reference_code; piece names render with the reference in front via comReferencia/NomePeca/useReferencias (pecas_referencias, batched, reference only). Maleta lookups go through maletas_buscar (kit.view + kit_cycle_in_scope; number, label, consultant name or code); consultant names on staff screens use comCodigo with useCodigosPessoas/useCodigosPorMaleta. Why: the team works by reference and consultant code; one shared path keeps every screen consistent.
- Reference/code in read-only RPC payloads (0346–0349): referral commission item snapshots carry variant_id + referencia (peca_referencia_etiqueta); central_vendas, indicacao_painel_admin return *_codigo fields rendered with comCodigo; fiscal read RPCs return 'consultora' already as "[Cód. X] Nome". Why: label rules without changing values or permissions.
- Name search (0378): server searches compare with public.busca_casa(campo, termo) (no accents, case-insensitive, every word in any order) and screen filters with normalizar/casaBusca from src/lib/busca-maletas.ts; never a bare ILIKE '%'||termo||'%' or toLowerCase().includes on names. Why: "fatima"/"FÁTIMA" must find "Fátima" in every screen and in the conciliation tables.
- Network clients (0382): every consultant_clients row has party_id (cliente_rede_garantir: reuse the party created by its Asaas payment, else a new party with role cliente; never matched by name/phone); the person page shows "Compras da cliente" from the read-only cliente_cockpit. Why: the Clientes menu and each client's purchases come from one source.
