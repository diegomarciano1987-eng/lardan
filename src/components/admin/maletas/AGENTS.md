# Maletas e remessas
- Remessa (table remessas, unique numero, one praça) is the parent of maletas: kit_cycles.remessa_id, opened only via remessa_abrir_maleta (consultant must belong to the remessa's praça, one maleta per consultant per remessa); print docs read número/praça/acerto from the remessa. Why: remessa is the master control entity.
- Referral (indicação) commissions are computed only by a DB trigger when a kit cycle closes, stored once per cycle in referral_commissions with an item snapshot; why: transparent, idempotent, never recalculated retroactively when tiers change.
- Maleta acceptance under signature mode goes only through kit_assinatura_finalizar (Clicksign signed file stored first; trigger on kit_acceptances blocks direct accept unless mode is desligado). Why: release requires the consultant's own signed term.
- Montagem-by-scanner goals come from montagem_metas_ciclo (0113): read-only, staff only, categories mapped by legado_categoria_tipo (Master edits via legado_categoria_tipo_definir, audited); on error the scanner falls back to remessa_parametros. The scanner overlay's only text input besides the barcode field is the composition search (0184: bip/nome/SKU/referência, client-side filter); the 400 ms refocus skips it and Esc returns to the barcode field. Why: suggestion never touches stock or the kit.
- Consultant maletas (0120): consultora_maletas/maletas_visibilidade are read-only; a Lardan maleta shows in the consultant app only in expedida/transito/recebida/operacao/acerto and when her active login is on the SAME party (duplicates hide it); SmallData open maletas exist only in legado_*. Why: explain "maleta não aparece".
- Lost maletas (0130): one row per lost maleta in maletas_perdidas (SmallData tipo perdida/status 11, or Lardan via kit_maleta_perdida); no NF; fiado = retail of pieces not returned, title sistema_origem maleta_perdida on FIADO-PERDA (outside DRE) + cob_fiado_linhas lote maleta_perdida, idempotent; skip-acerto via kit_pular_acerto / legado_maleta_pular_acerto (next acerto of the same praça); remessa maletas may go to the representante without consultora (remessa_abrir_maleta_representante) and he assigns a consultora or own candidata via rep_maleta_repassar.
- Consignment order sheet + price (0157): the A4 order is built by src/lib/pedido-consignacao.ts from kit_pedido_dados (items grouped by type via pedido_grupo_peca, prices = unit_reference_cents recorded in the kit composition, commission tiers from consultora_comissao_faixas, fixed texts from pedido_config — Master only via pedido_config_salvar); first column uses peca_referencia_etiqueta (variant reference_code then product reference_code, never legacy_code/SKU; missing = Sem referência) per 0170. Per-user order phone changes only the printed contact, not montage authorship; the configurable minimum-sales notice is informational. 'Postar a maleta até' only when remessas.tipo_envio = 'correio' (acerto − prazo_correio_dias). Consultant app, showcase, client orders and lost-maleta value use kit_preco(cycle, variant) (recorded price), never the catalog price of the day. Price rule preco_regra_lardan (0172: always down to the previous R$5 step ending 4,90/9,90; step values and prices below R$5 unchanged; never raises) is applied only via preco_reajuste_aplicar (Master, typed confirmation, after the preco_reajuste_previa report is approved), logged in preco_reajustes, undo by lote; shipped kits keep their recorded price, kits still in montagem move to the new price. Why: kits settle at the price on their label.
- Settlement in the app / pre-baixa (0158): kit_pre_baixas + kit_pre_baixa_itens per cycle; the consultant marks sold pieces (pre_baixa_vender; paid/concluded app orders are pre-marked and can't be lowered), closes with pre_baixa_fechar (sold at recorded price, commission tier on the consultant's whole remessa, payable = sold − commission → receivable title sistema_origem pre_baixa via the cobrança config actor; Pix via preBaixaFecharPix + pre_baixa_asaas_preparar). Staff confer by scanning (pre_baixa_conferir preview/apply): expected return = sent − declared sold; missing = sold at recorded price, declared-sold that came back = refund; returned pieces go back through kit_retorno/kit_retorno_confirmar, qty_sold is set, cycle closes; any difference → 'pendencia' (receivable for the difference or credit noted) resolved via pre_baixa_pendencia_resolver. New kit requires the previous kit's pre-baixa closed only when pedido_config.exigir_pre_baixa is on (Master; one-time release pre_baixa_liberar_kit). Why: exact settlement before the kit is back, divergence becomes a traceable pending item.

- Consultant app (0159): a client order paid to Lardan (Asaas allocation on sales_orders.pay_installment_id) turns pago/concluido by trigger pedido_pagamento_sincronizar (reversal → estornado); "cliente pagou em dinheiro" only via consultora_pedido_pago_dinheiro (pay_method 'dinheiro', money stays with the consultant, never on an order that already has a Lardan charge). The acerto deducts what clients already paid to Lardan (pre_baixa_recebido_lardan → kit_pre_baixas.recebido_lardan_cents; payable = sold − commission − received; ≤ 0 creates no title). consultora_meu_financeiro / consultant_home are owner-scoped (my_party_id); 2ª via only for her own receivable via consultora_debito_cobranca + server-only consultora_debito_asaas_preparar. Referral: "Quem te indicou?" text is kept in leads.indicado_por_texto and links only on an exact referral_code; the referred lead/profile inherits the sponsor's representative/praça only when empty; madrinha corrected only via consultora_madrinha_definir (registry.manage, audited). Leader path: criteria in lider_config (Master), leader status in lideres (request by the consultant, decision only by Master via lider_decidir); Minha equipe only for approved leaders and shows first name + initial; leader commission is stored but off. Liga levels in liga_niveis (Master via liga_niveis_salvar) count settled cycles in 12 months (Lardan pre-baixa + SmallData legado_maletas). Why: the app must show real money and real pending items without exposing other people's data.
- Review fixes (0163): a client payment (Pix/card trigger or "pagou em dinheiro") marks the order pago but never concludes it (conclusion still requires the sale record, as in order_set_status); aguardando_pagamento → em_atendimento. Conference recomputes what clients paid to Lardan (pre_baixa_recebido_lardan) so a payment after closing becomes a credit, never a double charge; a pre-baixa with payable ≤ 0 counts as paid. Cash received by a representative on an installment with an open Asaas charge returns aviso_asaas and opens a cob_tarefas to cancel the link. Why: no double charge, no orders stuck in "concluído" without the sale record.

- Argox labels (0173): printed raw (PPLB/PPLZ, 8 dots/mm, 100×12 mm) through QZ Tray via src/lib/argox-direta.ts, signed server-side by assinarQz (QZ_PRIVATE_KEY; public cert public/qz/lardan-qz.crt); printer name/language are per workstation; PDF (etiquetas-pdf.ts) only for the ruler fallback; calibration is company-wide in pedido_config.etiqueta_calibracao via etiqueta_calibracao_salvar (Master or kit managers, audited), localStorage only as offline fallback. Why: one setup serves every collaborator login.

- Remessa finalization (0184): remessa_finalizar (kit managers, typed remessa number, all maletas conferida or later) sets status fechada = "Finalizada" (no new maletas, no envio change); only Master reopens via remessa_reabrir with motivo (restores previous status from audit). Consultants with no praça are brought into the remessa's praça only via remessa_vincular_consultora (never moves someone who already has a praça or another representative). kit_reference_price falls back to products.price_cents when the variant has no price. Why: stop zero-priced pieces and blocked remessas without touching shipped kits.
- Collaborator scope (0188): colab_praca_ok uses colab_praca_ids() (rep_praca_ids) and legacy SmallData scope uses colab_legacy_rep_codigos() (legacy rep by party OR same name as the collaborator's representative). Why: duplicated representative records blocked remessas ("Remessa fora da carteira") and hid SmallData history.
- Remessa printer preferences are workstation-local names, never device selection; documents and labels confirm separate destinations before browser print. Official global Pix is cached via a service-only audited RPC after Master, MFA and Asaas preflight; print reads are kit-scoped and never settle debt. Why: browsers cannot choose two physical printers and global payer identity is not a receivable allocation.
- One-click delivery (0190/0191/0193): kit_liberar_consultora (kit managers) chains kit_expedir → kit_transfer_confirm/forward up to 'recebida' and logs maleta.liberada_equipe with actor e-mail; it never accepts — the consultant always confirms receipt herself in the app. Why: her own acceptance is the mandatory proof of receipt.
- 0199 security: consultora/representante hold kit.view only for their own maleta. Operation list RPCs (remessas_lista/buscar, remessa_maletas, praca_consultoras, maleta_total_sugerido + colab_party_ok, kit_depositos_operacao) and the remessas table gate on kit_ve_rede() (full staff or code collaborator), never on kit.view alone; is_staff excludes consultora/representante; kit_conferir/expedir/item_upsert/liberar check kit_cycle_in_scope. Why: 100+ logged-in consultants must not see each other.
- 0200 client payment after the acerto conferência: acerto_ajuste_conciliar(order) compares the expected credit/debit (paid now vs paid at conferência, from sales_order_events) with consultora_acerto_ajustes and writes only the difference (idempotent, rows immutable). Credit = 'abatimento' adjustment on the open installments of that pre-baixa's own titles, remainder to return → pre-baixa status pendencia + motive; debit = consume unreturned credit, rest becomes a receivable title (fin_title_create, sistema_origem pre_baixa_ajuste). Never touches the conferred numbers of kit_pre_baixas; never blocks the Asaas settlement (failure → audit_logs pre_baixa.ajuste_falhou; Master reruns acerto_ajustes_reprocessar, preview first). App orders count open orders of the same piece. Why: the client's money must never be charged twice and the conferred acerto stays an immutable snapshot.
- 0201 cockpit numbers: post-conferência commission = pre_baixa_comissao_final(p) (vendido_final − valor_final − recebido_lardan), never p.comissao_cents; SmallData sales in the app follow legado_acertos_distribuir (only fonte 'cobranca' once that import exists); legacy codes always via legado_codigos_da_pessoa. Why: every screen must show the same numbers.

- Praça by address (0207/0208): a consultant without praça gets it from her primary address city/UF only when exactly one active non-internal praça lists that city in legado_pracas.cidades (praca_pela_cidade); shared or unlisted cities stay manual; an existing praça is never changed. Missing city is filled from cep_cidades (learned by the geocode drain via BrasilAPI). praca_consultoras has no 200-row cap and searches by accent-free word parts. Why: new consultants must reach the montagem without guessing.
- Abertura (0224): a maleta with the representante and no consultora prints pedido and promissória with consultant fields BLANK (kit_pedido_dados/kit_consultora_doc return abertura=true; patched from the live definition, idempotent); a maleta with neither consultora nor representante is refused. No NF while in abertura; when the rep links a consultora (rep_maleta_repassar) the fiscal queue trigger (status OR consultora_party_id) enqueues the remessa if production+automático is on. Rep app: mobile shows only Captação, Agenda, Convite, Abertura; Abertura = receive + link (MaletasRepresentante) + send contrato/promissória via ZapSign. Why: reps open new consultants in the field with paper first.
- Representative custody (0254–0257): remessas with a representante (not Correios) leave via remessa_expedir_representante / kit_expedir rota representante (no direct "Confirmar entrega"); the rep confirms receipt (kit_transfer_confirm), delivers by hand (kit_transfer_forward, "Entreguei em mãos"), then the consultant confirms receipt and accepts. consultora_aceites_pendentes blocks her app only when a transfer to her is in transit or the kit is recebida. showcase_items_for shows unaccepted pieces as em_breve (divulgação, no purchase); purchase only with accepted qty_available. Mistaken direct delivery is undone only via kit_devolver_custodia_representante (no acceptance/signature, motivo, audited transfer). Why: physical custody must match the system.
- 0266: remessa_maletas returns abertura_numero and maleta_seq (row order of the consultant's maletas in the remessa); the remessa screen labels rows "ABERTURA 0N" / "MALETA 0N" (rotuloMaletaRemessa). The pedido header shows "Remessa X · Abertura 0N"; the maleta label no longer prints the loose maleta number (maleta_numero is still returned, not printed). One maleta per consultant per remessa stays enforced (kit_cycles_remessa_consultora_uq), so MALETA 02 only appears if that rule changes. Why: Daniel, 08/11.
- Maleta transfer (0279): one engine maleta_transferir_exec (service-only) behind remessa_maleta_transferir (kit managers/Master, reason required, any consultora of the remessa's praça or ABERTURA with the representative) and rep_maleta_trocar_destino (own carteira); maleta_transferir_previa explains blocks/effects. Allowed until the consultant's acceptance (montagem → conferida → expedida → transito incl. unconfirmed hand delivery → recebida without acceptance; recebida returns custody to the rep); blocked by acceptance, sale, pre-baixa, active Correios or NF in progress. Authorized remessa NF never edited/auto-emitted: it becomes one open maleta_troca_pendencias (updated, never duplicated, on repeated transfer). Old promissória: pending → refused at ZapSign (queue retried by the 10-min zapsign cron), signed → kept as proof with invalidada_em; the new one is sent by maletaTransferir. Why: Diego/Daniel, 11/11 — the maleta changes hands in the street, fiscal/legal records stay intact.
- 0280/0292: remessa/representante of a ready maleta changes only via remessa_maleta_mudar_remessa (kit managers, before acceptance; pieces untouched; custody moves to the new rep when the maleta is with the old one; the consultora's carteira and praça follow the new remessa's representative via consultora_carteira_seguir, audited, never for bloqueada/desligada). rep_maleta_repassar also moves an existing cadastro to the delivering rep. remessa_maletas shows every maleta of a remessa to its collaborators (colab_cycle_ok). Why: Daniel, 12/11 — a maleta moved to another rep vanished from his montagem and carteira. A non-accepted maleta (expedida/transito/recebida) goes back to the company via maleta_devolucao_pedir (rep of the carteira or staff) → maleta_devolucao_receber (kit managers only): stock returns to origin, cycle cancelada, promissória invalidated, authorized remessa NF becomes a maleta_troca_pendencias row (origem devolucao); never auto-emits NF. Correios ida also from transito; delivery sets due_at = entrega + 30 days only when the maleta has no representante. Why: Diego, 11/11.
- Return path (0281): maletas come back consultora → representante → empresa. The rep registers a retorno_expedicoes batch via retorno_expedir (items = retorno_a_devolver: pre-baixa 'fechada' or maleta_devolucoes 'pedida'; an undelivered maleta in his custody becomes a 0280 devolução with motivo). Qualidade (quality.manage) or montagem (kit.manage) confirm arrival only via retorno_receber (scan kit code; arrival without batch creates an origem 'balcao' batch): nao_ficou → maleta_devolucao_receber (stock back), acerto → piece conference stays pre_baixa_conferir (kit.manage). One live item per cycle (a_caminho/recebida); retorno_nao_veio returns it to the rep's pending list. Never emits NF or touches money. Why: everything that left with the rep must come back and be confirmed in one place.
- Stock entries never fail on uncounted negative balances (0281 apply_stock_delta refuses only negative deltas that end below zero). Why: returns into the depot were blocked by legacy negative stock.
- 0283: a second maleta for a consultora in the same remessa only via remessa_maleta_segunda / rep_maleta_segunda with a written motivo (kit_cycles.segunda_maleta_motivo exempts the unique index). A devolução made by mistake is undone only by the Master (maleta_devolucao_desfazer: pieces back to the maleta, fiscal pendency stays open), then the normal Transferir. Test sales/empty remessas are cancelled logically (venda_teste_excluir, remessa_cancelar_vazia), never deleted. Sales history of another cadastro (different CPF) is linked via consultora_historico_vincular; debts stay on the original party. Why: Diego, 11/11 — fix mistakes without losing audit or mixing legal identities.
