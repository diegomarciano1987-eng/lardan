# Teste de candidatura (0284)
- The candidate test (Daniel's 30/09/2026 spec) lives in candidatura_testes: one open test per lead, random 64-hex token, public page /candidatura/<token> served only through teste.functions.ts (service client, token is the only key, first name only). Answers are stored as option codes; scores are computed only on the server by src/lib/candidatura-teste/calculo.ts with parameters from candidatura_teste_config (new row = new versao_teste; defaults in padrao.ts). Why: the candidate cannot change her result and every analysis can be recalculated.
- No result approves or rejects by itself and never becomes a refusal reason. Staff read everything (candidaturas.view); the representative reads only rep_candidata_perfil (DISC profile, rede faixa, acompanhamento, sonho) — never risco, restrição or O1–O5. Why: spec permissions and LGPD.
- Links: site creates the test only for a NEW lead with the WhatsApp consent (never for a re-submission); staff (candidaturas.edit) or the lead's representative generate via candidatura_teste_gerar. Conclusion moves open leads from early stages to Documentação (candidatura_teste_concluido). Why: one card, one link, no hijacked links.
