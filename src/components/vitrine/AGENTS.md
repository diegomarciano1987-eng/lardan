# Vitrine, área da consultora e ajuda

- Showcase purchase (0211, Diego 05/11): the public page sells through the server function vitrineComprar → service-only vitrine_comprar (published showcase, client name/WhatsApp/valid CPF, same CPF rules as consultora_pagamento_titulo, limits 2 unpaid per phone / 15 per showcase) and the official Asaas engine (Pix/card in Lardan's name, title PED-<code>). The order (channel 'vitrine', client in her carteira) holds the piece for 60 min via pedidos_abertos_qtd (the single open-order count for app + showcase); /api/public/vitrine/expirar (every 10 min) cancels the Asaas charge and expires unpaid orders, and also cancels charges of any cancelled order still open. Paid → counts as sold in the pre-baixa and abates the acerto; the consultant only delivers (consultora_pedido_entregue). The legacy anonymous showcase_order_create stays revoked. Why: real sales from the link without double-selling a piece or leaving payable charges on cancelled orders.
- Consultant showcase design lives as draft/published jsonb on consultant_showcases, written only via showcase_design_* RPCs that re-validate against a fixed whitelist; why: atomic publish.
- Showcase images sit in the private vitrine-originais bucket and reach the public only through /api/public/vitrine-img for paths in a live published design; why: public buckets are blocked and drafts must stay private.
- Help content lives in help_articles (audience publico|consultora, rascunho|publicado, RLS by audience, edited only by can_manage_content); screens open it in a side sheet via BotaoAjuda so in-progress forms are never lost.
- Consultant area uses the .area-consultora scope and keeps the active tab in ?aba= so back/refresh return there.
- Showcase addresses are checked by showcase_slug_reserved (site routes, categories, pages, showcase_slug_history); why: one consultant's link can never be taken by another.
- Product photos are served publicly by /api/public/midia only via media_publica_ok (published product/hero, or variant currently available in an operating kit cycle); why: draft catalog stays private while consultant showcases always show their pieces.
- Consultant piece photos (0298): stored in vitrine_fotos_proprias (one per party+variant, owner-only RLS, written only via vitrine_foto_propria_salvar/remover: path `<party>/peca/<uuid>.webp` in vitrine-originais, file must exist, variant must be in one of her maletas); showcase_items_for returns foto_propria, VitrineView shows it before the official photo, and /api/public/vitrine-img serves it only while her showcase is public (showcase_public_file_ok). Never write to products/product_variants/product_media. Why: fotos caseiras só na vitrine dela, catálogo oficial intocado.
