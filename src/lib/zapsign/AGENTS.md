# Assinatura digital (ZapSign) — 0224
- Contrato (per consultora) and promissória (per maleta) are created from assinatura_modelos (markdown with {{campos}}, Master edits via assinatura_modelo_salvar; seeded contrato is a DRAFT for legal review) through POST /api/v1/docs (markdown_text), signer link sent by WhatsApp (send_automatic_whatsapp) and copyable. Why: no PDF generation, consultant signs on the phone.
- Who: assinatura_pode = staff (master/diretoria/financeiro/kit.manage) or the consultant's own representante (rep_portal_pode + consultant_profiles.representative_party_id). Registration/return/reading are service-only (assinatura_registrar/retorno/pendente/ler). One pending per (party, tipo, cycle); resend cancels the previous one (substitui). Why: no duplicate documents, privacy.
- Webhook /api/public/zapsign/webhook?chave=ZAPSIGN_WEBHOOK_SECRET never trusts the payload: it re-reads the document from the API (detalharDocumento) before assinatura_retorno; signed never regresses. Signed file links expire in 60 min: zapsignArquivo fetches a fresh one. Secrets: ZAPSIGN_API_TOKEN, ZAPSIGN_AMBIENTE (producao|sandbox), ZAPSIGN_WEBHOOK_SECRET — never in code or chat. Why: provider security and legal record.
- 0228: every signed document lands in the signer's cadastro (tab "Documentos assinados", RPC documentos_assinados_da_pessoa = assinaturas_digitais + kit_signature_requests). Documents created straight in the ZapSign panel are imported as tipo 'avulso', origem 'zapsign_painel'; the signer is matched by CPF, then a unique phone (last 11 digits), then a unique email — ambiguous = no match, never guess. A copy of each signed PDF is kept in the private bucket "assinaturas" at `${partyId}/${docToken}.pdf` and written once only. Who sees it: Master/registry.view/finance.view and the consultora's own representante; not the consultora herself. Why: ZapSign links expire and the record must survive the provider.
- Document reads also require colab_party_ok; multi-signer imports stay in review, ambiguous identities stop fallback, and pending avulsos do not share the contract/promissory lock. Downloads allow only provider HTTPS storage, no redirects, timeout, 20 MB and PDF signature validation; existing copies open without contacting ZapSign. Why: preserve portfolio privacy, availability and immutable evidence.
- Confissão de dívida (0232/0233): tipo 'confissao' per cob_simulacoes acordo (simulacao_id, one pending per acordo), text from assinatura_modelos 'confissao' (draft, Master edits; extra fields {{dividas}}/{{plano}} built by cob_confissao_dados, cob_pode only). - 0251: contrato/promissória fields {{email}}, {{rg}} (with issuer), {{estado_civil}}, {{data_nascimento}} (+ _extenso) come straight from the person's cadastro via assinatura_dados; empty stays a blank line. Why: Dr. Danilo's new contract.
- Acordo judicial (0318–0320): tipo 'acordo_judicial' per cob_judicial_acordos (judicial_acordo_id, one pending per acordo) sends the lawyer's PDF exactly as attached (cob_judicial_docs, tipo minuta_acordo; sha256 kept as texto_hash) via base64_pdf — never re-typed into a template. Gate is cob_pode via cob_judicial_assinatura_dados; debtor uses token WhatsApp (email fallback) + selfie + document; lawyer is an optional email signer. Resend/cancel of the acordo invalidates the old link and queues a ZapSign refusal. Why: legal text stays the lawyer's and no debtor signs two versions.
